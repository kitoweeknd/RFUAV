# RFUAV ChannelSim Viewer - Product Requirements Document (PRD)

> Version: v1.3 | Date: 2026-04-09 | Status: Draft

---

## 1. Project Overview

**Project Name:** RFUAV ChannelSim Viewer

**Project Type:** Desktop Visualization Tool (Python + PySide6/Qt, runs on local Python environment)

**Core Functionality:** Load local IQ binary files, configure and stack 8 types of channel degradation effects via interactive UI, display real-time time-frequency spectrograms and diff comparisons for original and processed signals, and support exporting processed IQ data.

**Target Users:** Wireless communication algorithm engineers, RF physical layer researchers, communication waveform design and verification personnel.

## 2. Functional Scope

### 2.1 Channel Simulation Module

| ID | Channel Type | Backend Entry Function | Configurable Parameters | Default Value |
|----|-------------|----------------------|-----------------------|---------------|
| 1 | **AWGN** | `apply_awgn()` | SNR (dB) | 15 dB |
| 2 | **CFO** | `apply_cfo()` | Frequency offset CFO (Hz) | 15 kHz |
| 3 | **Fading** | `apply_rayleigh_or_rician_fading()` | Fading type (Rayleigh/Rician), K factor, block size | Rayleigh, K=5, block=256 |
| 4 | **Multipath** | `apply_multipath()` | Max delay (samples), number of paths, exponential decay | delay=20, n_paths=4, decay=0.35 |
| 5 | **Phase Noise** | `apply_phase_noise()` | Phase std dev per sample (radians) | 0.002 |
| 6 | **IQ Imbalance** | `apply_iq_imbalance()` | Amplitude imbalance (dB), phase imbalance (degrees) | 1.0 dB, 3.0° |
| 7 | **Crop+TimeShift** | `apply_random_crop_and_time_shift()` | Min keep ratio, max time shift | 0.7, 300 samples |
| 8 | **Doppler** | `apply_doppler()` | Doppler shift (Hz), Doppler spread (Hz), Jakes model switch | 0 Hz, 100 Hz, Off |

- Each channel effect can be independently toggled (enabled/disabled) for quick comparison.
- All parameters adjustable in real-time via UI controls (sliders + input boxes).
- Channels are applied serially in fixed order: `preprocess → fading → doppler → multipath → cfo → phase_noise → iq_imbalance → awgn → crop_time_shift`.
- Global random seed configurable (for reproducibility).

### 2.2 Signal Preprocessing Chain

Before channel simulation, some scenarios require preprocessing the input signal. Preprocessing acts as an independent operation unit at the front of the channel chain:

| Preprocess Operation | Description | Configurable Parameters | Default Value |
|---------------------|-------------|------------------------|---------------|
| **Digital Filtering** | Bandpass/lowpass/highpass FIR/IIR filtering | Filter type (Chebyshev/Butterworth), cutoff frequency, transition bandwidth | Off |
| **Resampling** | Change sampling rate (up/down sampling) | Target sampling rate, filter type | Off (keep original rate) |
| **Gain Control** | Manual amplitude scaling | Gain value (dB) | 0 dB |
| **DC Bias Removal** | Remove IQ DC component | Enable/disable | Enabled |

> **Processing Order**: Preprocess → Channel Simulation Chain → Export. Preprocess results can be viewed in the intermediate stage selector.

### 2.3 Signal Input/Output

- **Input:** Local `.iq` binary file (float32 interleaved format: `I0, Q0, I1, Q1, ...`).
- Supports manual setting of sampling rate `fs` and center frequency `fc` (UI input boxes).
- Input signal info (sample count, duration, power) displayed on interface in real-time.
- **Export Processed IQ:** Supports exporting final stacked result or IQ data from any intermediate stage as `.iq` binary file.

### 2.4 Visualization Display

Each display type can simultaneously show **original signal** and **channel-processed signal** (left-right/top-bottom split comparison):

| Display Type | Description | Backend Logic |
|-------------|-------------|---------------|
| **Time Domain Envelope** | `|x(t)|` amplitude over time | Direct plot |
| **Power Spectral Density (PSD)** | FFT magnitude spectrum (dB), Hanning window | `np.fft.fft + window function` |
| **STFT Time-Frequency** | Short-Time Fourier Transform spectrogram | Reuses `visualization.plot_time_frequency` |
| **Original vs Processed Comparison** | Left-right subplot overlay, visual diff display | Generated by each stage in pipeline |
| **Residual/Diff Spectrogram** | Spectrum of difference before/after processing | Compute `\|FFT(original) - FFT(processed)\|` |

STFT uses default parameters: `nperseg=256, noverlap=192`, adjustable in UI.

### 2.4.1 Spectrogram Interaction Enhancement

On top of basic spectrogram display, enrich interactive features for improved signal analysis precision and efficiency:

| Interaction Feature | Description | Implementation |
|--------------------|-------------|----------------|
| **Cursor Readout** | Mouse hover shows frequency/time/amplitude coordinates | `mpl_connect('motion_notify_event')` captures mouse position, updates coordinate display dynamically |
| **Peak Markers** | Auto-annotate spectrum peak frequency and amplitude | `scipy.signal.find_peaks` peak detection, results annotated on spectrogram |
| **Frequency Axis Zoom** | Zoom to specific band, drag to pan | `ax.set_xlim` + mouse wheel zoom, `panalytics` pan |
| **Dynamic Playback** | Long signal playback animation, sliding STFT window | QTimer-driven STFT window slide, adjustable playback speed |
| **Region Selection** | Box-select specific spectrogram region for local zoom | `mpl_connect('button_press_event')` box selection logic |
| **Crosshair Cursor** | Show vertical/horizontal reference lines, assist reading | Matplotlib `axvline` + `axhline` |

> **Performance Note**: Interactive events (mouse move, zoom) also require 200ms debounce to avoid frequent redraws.

### 2.4.2 Channel Quality Assessment Metrics Panel

Spectrograms provide visual display, metrics panel provides quantified signal quality evaluation. Add independent **statistical metric cards** below signal overview area, calculated and displayed in real-time:

| Metric | Calculation | Physical Meaning | Typical Threshold |
|--------|-------------|-----------------|------------------|
| **EVM (%)** | $\sqrt{P_{error}/P_{reference}} \times 100\%$ | Modulation signal quality assessment | ≤5% (good), ≤10% (acceptable) |
| **Crest Factor** | $10\log_{10}(P_{peak}/P_{avg})$ | Signal dynamic range | 6-10 dB (OFDM), 12-15 dB (QAM) |
| **ACLR (dBc)** | $10\log_{10}(P_{adj}/P_{main})$ | Adjacent channel leakage ratio | ≥45 dBc (4G/5G standard) |
| **Signal Power (dBFS)** | $10\log_{10}(P_{signal}/P_{fullscale})$ | Signal level (full scale reference) | -3 dBFS (peak safety threshold) |
| **ACPR (dBc)** | Equivalent to ACLR | Adjacent channel power ratio | Common metric in communication standards |
| **Adjacent Channel Power (dBm)** | Integrate adjacent band power | Out-of-band emission absolute value | — |

> **Implementation Note**: Metrics like EVM and ACLR require both original reference signal and processed signal; computed in pipeline `finished` signal callback, `processing_worker.py` handles calculation logic, `signal_info_panel.py` displays results.

## 3. Non-Functional Requirements

### 3.1 Performance Requirements (Core Priority)

> High performance is the primary non-functional requirement of this system, pervading entire design.

| Metric | Target | Implementation |
|--------|--------|----------------|
| Parameter adjustment → Spectrogram refresh latency | ≤ 1 second (within 1M samples) | Background thread + NumPy vectorized computation |
| Large file processing (>1 GB) | No stutter, controlled memory usage | Reuse `run_channel_pipeline_streaming` chunked processing + progress feedback |
| Spectrogram redraw frame rate | No tearing / latency perception | Matplotlib `blit=True` incremental refresh + `QtAgg` hardware acceleration |
| Memory peak | ≤ 3x input file size | Stream read/write, intermediate signals generated on-demand, avoid unnecessary copies |
| Startup time | ≤ 3 seconds | Lazy import non-core modules (PyYAML, scipy, etc.) |

#### 5.3.2 Signal/Slot

```python
# Key signal definitions
from PySide6.QtCore import Signal, QThread
from typing import Any, Dict, Optional
import numpy as np

class ProcessingWorker(QThread):
    """Background processing thread, processes IQ signal and updates spectrogram"""
    finished = Signal(np.ndarray)                    # Processing complete, carrying result data
    progress = Signal(float, str)                   # Progress update (percentage, current stage name)
    error = Signal(str)                             # Error message
    metrics_ready = Signal(dict)                     # Metrics calculation complete

    def __init__(self, iq_data: np.ndarray, config: Dict[str, Any], parent=None):
        super().__init__(parent)
        self.iq_data = iq_data
        self.config = config

class MainWindow(QMainWindow):
    """Main window, manages all UI components and signal connections"""
    # Menu/toolbar signals
    load_iq_triggered = Signal(str)                 # Load IQ file
    export_iq_triggered = Signal(str, int)          # Export IQ file, params: path, stage_id
    export_fig_triggered = Signal(str, int)         # Export image, params: path, view_type

    # Parameter change signals (with debounce)
    stage_config_changed = Signal(dict)              # Channel config changed
    preprocess_config_changed = Signal(dict)         # Preprocess config changed
```

#### 5.5.3 FFT and Spectrum Calculation

```python
def compute_psd(signal: np.ndarray, fs: float) -> tuple[np.ndarray, np.ndarray]:
    n = len(signal)
    windowed = signal * np.hanning(n)
    spectrum = np.fft.fft(windowed)
    psd = np.abs(spectrum[:n//2]) ** 2 / (np.sum(np.hanning(n)**2) * fs)
    psd_db = 10 * np.log10(psd + 1e-12)
    freqs = np.fft.fftfreq(n, 1/fs)[:n//2]
    return freqs, psd_db

def compute_stft(signal: np.ndarray, fs: float,
                 nperseg: int = 256, noverlap: int = 192):
    from scipy.signal import stft
    freqs, times, Zxx = stft(signal, fs=fs, nperseg=nperseg,
                              noverlap=noverlap, return_onesided=False)
    Zxx_shifted = np.fft.fftshift(Zxx, axes=0)
    stft_db = 20 * np.log10(np.abs(Zxx_shifted) + 1e-12)
    return np.fft.fftshift(freqs), times, stft_db
```

#### 5.5.4 Memory Mapping and Streaming Processing

| Scenario | Method | Memory Usage |
|----------|--------|-------------|
| **Small files (<100MB)** | `np.fromfile()` | File size × 2 |
| **Medium files (100MB-1GB)** | `np.memmap()` | On-demand loading, peak < 500MB |
| **Large files (>1GB)** | Chunked processing | Chunk size × 3 |

```python
def load_iq_memmap(file_path: str, dtype='float32'):
    return np.memmap(file_path, dtype=dtype, mode='r', offset=0)

def run_pipeline_streaming(file_path: str, config: dict, block_size: int = 10_000_000):
    mm = np.memmap(file_path, dtype='float32', mode='r')
    n_samples = len(mm) // 2
    result = np.zeros(n_samples, dtype=np.complex128)
    for start in range(0, n_samples, block_size):
        end = min(start + block_size, n_samples)
        block = mm[start*2:end*2].view(np.complex128)
        result[start:end] = apply_pipeline(block, config)[:end-start]
        yield (end / n_samples, f"Processing: {end/n_samples*100:.1f}%")
```

#### 5.6.1 QThread Lifecycle

```python
class ProcessingWorker(QThread):
    finished = Signal(np.ndarray)
    progress = Signal(float, str)
    error = Signal(str)

    def run(self):
        try:
            result = self._process()
            self.finished.emit(result)
        except Exception as e:
            self.error.emit(str(e))

    def stop(self):
        self._should_stop = True
        self.wait(5000)
```

- Never do signal processing in main thread to avoid UI freeze
- Signal/Slot auto-handles cross-thread marshalling, no manual handling needed
- QThread more suitable for signal processing than Python threading

## 7. Key Technical Implementation Points and Notes

### 7.1 UI Development Notes

1. **PySide6 vs PyQt6 API Differences**: This project uses PySide6; note signal definition uses `Signal` not `pyqtSignal`.
2. **Qt Object Parent-Child Relationship**: All Qt controls must specify `parent` on creation to avoid memory leaks; layout manager takes deletion responsibility.
3. **QSS Style Isolation**: Custom styles for complex controls like sliders and dropdowns need precise `::subcontrol` subcontrol specification, otherwise styles may not apply.
4. **High DPI Screen Adaptation**: Set `QApplication.setAttribute(Qt.AA_EnableHighDpiScaling)` and `Qt.AA_UseHighDpiPixmaps` on main window creation, ensuring Retina/4K screen clarity.
5. **Dark Mode Adaptation**: For dark theme support, set via `QPalette` or switch QSS, don't modify Matplotlib rcParams (Matplotlib and Qt themes independent).
6. **Window Minimum Size**: Set `setMinimumSize(1200, 800)` to prevent spectrogram display issues in small windows.
7. **Lazy Import for Faster Startup**: `import yaml`, `import scipy`, `import matplotlib.pyplot` all imported on first use, not bulk imported at top of `app.py`.

### 7.2 Signal Processing Notes

1. **Data Type Consistency**: IQ data uses `np.complex128` throughout pipeline, avoid float32 precision loss.
2. **FFT Length Selection**: PSD FFT length uses signal own length (no zero-padding), STFT uses fixed `nperseg=256` window length.
3. **Spectral Leakage Control**: PSD calculation uses Hanning window (`np.hanning`), zero-pad to signal length after windowing then FFT.
4. **STFT Backend Consistency**: STFT parameters in `spectrum_data.py` (`nperseg`, `noverlap`, `return_onesided=False`) must exactly match `visualization.plot_time_frequency`, otherwise PSD peak dB values inconsistent.
5. **Residual Spectrum Normalization**: Residual `|FFT(original) - FFT(processed)|` needs dB conversion, `+ EPS (1e-12)` prevents log(0).
6. **Power vs Amplitude**: `normalize_power` uses `|x|^2` normalization, PSD uses `20*log10(|X|)`, both have consistent physical meaning.
7. **Large File Decimation**: Two thresholds `MAX_PLOT_POINTS = 2_000_000`, `MAX_STFT_COLS = 3_000` strictly control rendered data volume, prevent Matplotlib OOM.

### 7.3 Multi-threading Notes

1. **Never Wait for Sub-threads in Main Thread**: Never use `worker.wait()` + polling in main thread for progress, causes UI freeze.
2. **QThread Lifecycle**: `ProcessingWorker` after `finished` signal, main window responsible for `deleteLater()` destruction to avoid memory leaks.
3. **Signal Disconnect Timing**: Before starting new worker, must first `disconnect()` old worker all signals, prevent old worker callbacks to new window.
4. **Exceptions Cannot Cross Thread Boundaries**: Exceptions in `run_pipeline` must be caught within worker, transmitted to main thread via `error.emit()`, never let exceptions escape to Qt event loop.
5. **NumPy and QThread**: NumPy's GIL release characteristic makes `np.fft` etc. operations efficient in QThread, no extra handling needed.
6. **Avoid Operating Qt Controls in Sub-threads**: Only main thread can update QLabel/QLineEdit etc. controls, sub-threads trigger main thread Slot updates via Signal.

### 7.4 File I/O Notes

1. **File Path Encoding**: Windows Chinese path support, `file_path` uses `Path` object, `open(..., encoding='utf-8')`.
2. **IQ File Validation**: After read check `len(iq) < 2` then error; if file size odd bytes, discard last byte (consistent with `io_utils` behavior).
3. **Export Overwrite Confirmation**: If file exists on IQ/chart export, popup `QMessageBox.warning` confirm overwrite.
4. **Large File Write**: `save_interleaved_iq` uses `np.tofile()` direct binary write, 3-5x faster than `with open()` + `write()`.
5. **YAML Security**: Use `yaml.safe_load()` not `yaml.load()`, prevents arbitrary code execution vulnerability.

### 7.5 Performance Optimization Checklist

| Check Item | Target | Verification |
|-----------|--------|---------------|
| Startup time | ≤ 3s | `time python -m ChannelSimulation.viewer.app` |
| Spectrogram refresh delay (1M samples) | ≤ 1s | Measure parameter change to plot refresh completion |
| Memory usage (100M samples) | ≤ 500MB | `taskmgr` or `tracemalloc` |
| Memory usage (1GB file) | ≤ 300MB (memmap mode) | Same |
| Slider drag no stutter | Frame rate ≥ 30fps | Visual observation, plot follows drag without tearing |
| Large file progress feedback | Update once per second | Timed verification |

### 7.6 Debounce and Batch Update Strategy

Debounce and batch update mechanism for parameter changes ensures optimal performance:

| Scenario | Strategy | Implementation |
|---------|----------|----------------|
| **Slider drag** | Debounce 200ms | Trigger recalculation after drag ends, avoid frequent updates |
| **Input box modification** | Debounce 200ms | Trigger after blur or Enter |
| **Dropdown selection** | Immediate trigger | No debounce needed, single operation |
| **Batch paste/load config** | Cancel pending task | Immediately cancel old pending task, only execute new |
| **Config override** | As single undo operation | Load config as one complete parameter modification |

> **Note**: Use `QTimer.singleShot` for debounce implementation, not `QTimer` loop.

### 7.7 Memory Leak Prevention

The following measures prevent memory leaks, ensuring long-running stability:

| Check Item | Method | Verification |
|-----------|--------|--------------|
| **Qt Object Parent-Child** | All controls specify `parent=` parameter on creation | Use `tracemalloc` detection |
| **Matplotlib Figure Cleanup** | Call `plt.close('all')` before each spectrogram update | Memory profiler detection |
| **NumPy Array Lifecycle** | Avoid capturing large array references in closures | Code review |
| **QThread Resource Release** | `worker.deleteLater()` + `wait(5000)` | Long-running stability test |
| **Signal Connection Cleanup** | Disconnect old connections: `worker.disconnect()` | Execute before each new worker start |

## 8. Risks and Constraints

1. **Memory Constraint**: For super large files (>1 GB) use `np.memmap` memory-mapped read, avoid full memory load; beyond memory-mapped range use `run_channel_pipeline_streaming` and show progress bar.
2. **UI Responsiveness**: All signal processing executes in sub-thread (`QThread` + Signal/Slot), main UI never blocks; parameter changes through debounce (debounce 200ms) merge duplicate triggers.
3. **Backward Compatibility**: YAML format fully compatible with existing `channel_pipeline.sample.yaml`; users can export parameters configured in UI for CLI reuse.
4. **Python Environment**: Users need Python 3.10+ environment, install dependencies via `pip install -r requirements_viewer.txt` before running.
5. **Offline Deployment**: Completely offline operation, no network dependency, deployable in intranet isolated environments.
